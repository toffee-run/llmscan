# llmscan

TUI-инструмент, который оценивает, какая часть репозитория написана LLM.
Репозиторий только читается: ни одного файла в нём (включая `.git`) llmscan не создаёт и не меняет.

## Запуск

```sh
uv sync
uv run llmscan /путь/к/репозиторию          # TUI
uv run llmscan /путь --no-tui --top 30       # таблица в терминал
uv run llmscan /путь --json ~/report.json    # полный отчёт (вне репозитория)
uv run llmscan --list-detectors
```

Типовые конфиги инструментов (`*.config.*`, `.eslintrc.js`, `env.d.ts` и т. п.) пропускаются:
их одинаково копируют из шаблонов и люди, и модели. Вернуть — `--include-configs`.

Клавиши в TUI:

| клавиша | действие |
|---|---|
| `↑ ↓ ← →`, `Enter` | навигация, свернуть/развернуть каталог |
| `Space` | исключить / вернуть файл или весь каталог |
| `x` | исключить по маске (`tests/*`, `*.md`) |
| `a` | вернуть все исключённые |
| `s` | сортировка: имя → оценка → размер |
| `e` | экспорт JSON в `~/.local/state/llmscan/reports/` |
| `q` | выход |

Слева дерево с оценкой каждого файла и каталога, сверху — оценка по всему репозиторию
(среднее по файлам, взвешенное числом строк). Справа — почему: что сказал каждый детектор,
с номерами строк. Оценка с `?` и серой полосой — ненадёжная (мало кода или значение у самого
порога): такие файлы почти не влияют на общий итог и не попадают в «помечено». Исключённые файлы не участвуют в расчёте и не сканируются; список
исключений запоминается для каждого репозитория в `~/.local/state/llmscan/`.

## Детекторы

| имя | по умолчанию | что делает |
|---|---|---|
| `git` | да | коммиты с подписью ассистента (`Co-Authored-By: Claude`, Copilot, Cursor, aider…) и файлы агентов (`CLAUDE.md`, `.cursorrules`…) |
| `lm` | да | Binoculars на двух моделях `Qwen/Qwen2.5-Coder-0.5B` (+`-Instruct`), считается на GPU |
| `droid` | нет | классификатор `project-droid/DroidDetect-Base` (ModernBERT) |

Настройка без правки кода: `--detectors git,lm,droid`, `--set lm.device=cpu`,
`--set lm.threshold=0.9`, `--set droid.weight=2`.

### Насколько этому можно верить

Мало. Надёжный сигнал только один — `git`: подпись в коммите есть факт. Остальное на
проверочной выборке (235 файлов известных библиотек против 29 файлов, написанных LLM)
отработало близко к случайному: AUC `lm` 0.54, `droid` 0.63 (при 43%
ложных срабатываний). Выборка маленькая и смещённая, но чудес ждать не стоит: код от
современных моделей по содержимому отличается от человеческого плохо. Используйте оценку
как способ отсортировать файлы для ручного просмотра, а не как вердикт.

Проверить детекторы на своих данных и подобрать пороги:

```sh
uv run llmscan-eval --human ~/code/old-handwritten --llm ~/code/generated --detectors lm,droid
```

## Как добавить фичу

Любой новый сигнал — это детектор. Положите файл в `src/llmscan/detectors/`
(или в `~/.config/llmscan/detectors/`, если не хочется трогать пакет):

```python
from llmscan.detectors import Detector, register
from llmscan.models import Evidence, Finding, SourceFile


@register
class LongLines(Detector):
    name = "longlines"
    title = "Длинные строки"
    description = "Пример: люди чаще оставляют строки длиннее 120 символов."
    weight = 0.5
    options = {"limit": 120}          # меняется через --set longlines.limit=100

    def analyze(self, file: SourceFile) -> Finding | None:
        hits = [i for i, line in enumerate(file.lines, 1) if len(line) > self.opt["limit"]]
        if not hits:
            return None                # «нет мнения» — детектор не влияет на итог
        return Finding(score=0.2, confidence=0.5, summary=f"{len(hits)} длинных строк",
                       evidence=[Evidence("длинная строка", line=n) for n in hits[:5]])
```

Больше ничего править не нужно: детектор появится в `--list-detectors`, в TUI, в отчёте,
в кэше и в `llmscan-eval`. Дополнительные хуки: `prepare(root)` — загрузить модель или
прочитать историю один раз, `repo_notes()` — заметки уровня репозитория, `close()`.

## Устройство

```
repo.py      обход файлов (учёт .gitignore без вызова git), только чтение
detectors/   base.py — контракт и реестр; остальные файлы — по детектору
engine.py    цикл сканирования: дешёвые детекторы первыми, кэш по хэшу содержимого
scoring.py   сведение оценок детекторов в оценку файла / каталога / репозитория
storage.py   кэш и список исключений (всё в ~/.cache и ~/.local/state)
tui.py       интерфейс на Textual
cli.py       llmscan и llmscan-eval
```
